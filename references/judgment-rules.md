# 条件化审美判断

整理于2026-09-20；2026-09-21 增补 J13–J15 与 R04。来源是本会话的用户明确反馈及此前纷享销客/ShareHive/Neocrm改版反馈；下列摘录保留上下文，不将其泛化为所有项目的样式。

## 规则记录方式

每条记录：来源摘录、适用条件、判断、例外、用户确认范围、证据范围、冲突/替代关系。证据强弱与用户喜好不是同一轴：实际看清画面仍不等于用户喜欢；用户排除动画也不意味着已测量其速度。

## 工作流与通用判断

| ID | 判断与原因 | 条件、例外与确认范围 |
|---|---|---|
| J01 | 视觉改版以构图、章节、字体图像关系为主要交付，不能被工程修补替代。来源：用户强调“我想做视觉改版”。 | 用于明确的视觉改版；修bug任务不强制重设计。已确认工作方式。 |
| J02 | 根据实际需求自行筛选风格，提供真实参考，明确询问等待选择后才约定与制作。来源：“根据用户给出的需求内容自己筛选风格……让用户选择风格”。 | 用于未选风格的新设计/重大改版；已选风格的普通延展无需重复选择。已确认运行流程。 |
| J03 | 延展保持已选风格的身份，不让网站都长得一样。来源：“核心是复用我的审美判断，不是让以后的网站都长得一样”。 | 风格规则按项目生成，不预置统一配色、组件形状或卡片数量。 |
| J04 | 材质不能破坏阅读。来源：“想加一些质感……但是不想破坏整体的阅读感受”。 | 用于渐变、插图、纹理和玻璃；并非要求每页都有材质。 |
| J05 | 保留明确要求保留的正式文案，不通过删字消除布局问题。来源：官网改版的文案完整性要求。 | 若用户明确授权重写，可改文案；没有授权就保持原意与内容。 |

## 构图与材质的条件规则

| ID | 判断与来源 | 适用条件与例外 |
|---|---|---|
| J06 | 避免大卡遮住人物/产品主体，优先调整比例、位置和主次。来源：首屏卡片遮挡、画面杂乱的反馈。 | 图像承担主要证据时；并非禁止所有重叠，局部叠层可服务说明。 |
| J07 | 不做用户已否定的再次抠图/复杂合成；优先原素材和等比调整。来源：“不要再原图上修改”。 | 针对此前自制抠图导致重影与失真；后续用户提供匹配背景/人物独立图层并要求出框，允许按该次授权使用。不能把两次条件写成互相矛盾的全局禁令。 |
| J08 | 出框构图同时验证头部、动作、底边和相邻卡片。来源：要求男性头部完整、人物上方突破卡片但下缘停在底边。 | 仅用于匹配的Hero出框场景；具体top值和素材尺寸不是通用规范。 |
| J09 | 深底显式设置浅色文字，区分标题、正文和注释，检查实际对比。来源：“白色文字”。 | 深色区域，浅底仍按可读性安排；不是把全站文字设成白色。 |
| J10 | 彩色立体装饰使用规整几何、统一比例；玻璃实际覆盖背后图形，前景文字清晰。来源：“几何图形切的，规范化”和蒙层覆盖范围纠正。 | ShareHive同类产品能力卡；不否定其他项目有意采用的有机插画。 |
| J11 | 拒绝为显得科技而塞入无业务含义的科技素材图。来源：此前六角网格/神经网络图被否定。 | 该项目优先产品证据或克制抽象效果；不能由此默认所有项目采用光球/粒子。 |
| J12 | 内容型卡片优先用边框、留白和文案层级建立视觉重量，不靠彩色顶条+图标方块堆装饰。来源：Neocrm 行业卡片加了彩色渐变条和几何图标后被否定，"太像AI做的了，很丑"。 | 用于白底内容区的卡片（行业、资源、功能列表等）；Hero 区或品牌展示区的装饰性卡片不在此限。克制不等于禁止所有颜色，而是颜色要服务信息区分而非填充空白。 |
| J13 | 为页面引入新的图像生产方式（AI 生成插画、摄影、3D 渲染等）或更换区块视觉载体（插图 ↔ 产品界面 mockup ↔ 照片）属于图像体系变更，须先给 2–3 个命名方案（一句话画面+取舍）等待用户选择，不得直接实现。来源：Neocrm 营销服三卡制作中直接生成扁平插画被否定，"禁止用这种古老的插图，重新做计划"；经选项确认改用纯产品界面 mockup 后通过。 | 用于延展/制作中新增或更换视觉载体；已选定载体的常规延展不重复确认。纯 CSS 界面 mockup 是本次验证的候选之一（见 wps-home 案例项目应用记录）。 |

## 产品功能展示的选择规则

**J14 / 整体适配与使用者选择权**：2026-09-21，用户明确提供四类候选，要求“根据产出整体效果匹配适合的，也应该给使用者选择方案的权利”。先按数量、权重、文案、素材与章节节奏筛选，再给命名方案、参考、理由和取舍，等待选择；已选方案的常规延展不重复询问。适用范围是营销页面中的产品功能展示，不是全部 Hero 或应用界面。具体条件与六图证据见[产品功能展示候选](product-feature-options.md)。

这是对 J12/J13 的细化，不是替代：用户认可统一语义配图、固定区域滚动讲解、照片与 UI 大卡及邻近色轻毛玻璃卡。渐变、色彩分组、轻阴影可服务内容，不等于 R03 的无意义装饰；四类认可不等于当前项目已选、制作技术已定或相关交互已验证。

## 营销 Hero 的图像职责规则

**J15 / 先定主次，再用图像**：2026-09-21 用户提供四类 Hero：左文右图且配图简洁有质感；精致标题配下方产品界面，可用小插画点睛；真实人物与图形/界面结合；图像融入并辅助文案。按首屏主张、产品理解、场景关系与文案主次筛选，不仅按有无人像、上下/左右或颜色归类。保留用户编号和选择权，具体条件与证据见[Hero 候选](hero-options.md)。

适用范围为营销首屏候选，不是全站装饰许可：钉钉小插画是语义点睛，不推翻 R04；Slack 上下结构不构成全屏网格普遍背书，不推翻 J11；Fueler/Quicken 有人物仍属用户方案4，Copper 当前图无产品UI仍属方案3场景分支。人物增加信任是设计意图，未经实验不是因果结论。延展仍遵循 J13，不因入库就自动换图或生成素材。

证据范围：九图已读，Braze 仅有用户链接与归类；钉钉请求链接含占位符、实际地址未核验。保留素材、声明、交互与视口缺口。J15 是对本次 Hero 的新增确认，不把 J14 功能展示范围倒推扩大，也不改变 R01–R04 的原语境。

## 本轮明确反例

- **R01 / WPS首页Banner**：[实际繁中页面](https://zh-hant.wps.com/)。用户评价”展示方案太散”。作为注意力分散的具体反例，不能推导为禁止多模块、禁止白底或否定WPS所有页面。后续推荐不可复现该散乱关系；分散程度没有虚构数值阈值。
- **R02 / Airtable项目管理页动效**：[来源](https://www.airtable.com/solutions/project-management)。用户评价”动效过强”。避免复现该强度；不等于禁止所有动画、Tab或连续网格。未做完整运动测量，具体触发/幅度须重新观察。
- **R03 / Neocrm 行业卡片过度装饰**：2026-09-20 深色叙事改版中，给六张行业卡片加了彩色渐变顶条 + 几何图标方块 + 白卡浮于浅灰底。用户评价”太像AI做的了，很丑，和界面不符”。作为”模板感装饰”的具体反例——当内容型卡片用颜色填充而非信息区分时，会产生廉价模板感。不等于禁止所有卡片装饰；Hero 区、品牌展示区的装饰性处理仍按项目语境判断。
- **R04 / 扁平商务插画（AI 生成）**：2026-09-21 Neocrm 营销服三卡改版中，用 ImageGen 生成三张扁平商务插画（人物+图表组合）作卡片视觉层，用户否定”禁止用这种古老的插图”。作为”过时扁平企业插画”的具体反例——当功能模块需要产品视觉证据时，该风格不适用。不等于禁止所有插画、所有 AI 生图或其他插画风格（手绘、线描等未测）；边界待用户提供的插画反例进一步校准。证据：`references/evidence/rejected-flat-illustration-{mkt,sales,svc}.png`（ImageGen 生成原图归档）。替代方案与确认程序见 J13。

## 不提升为全局规则的历史决定

此前合并能力、采用箭头的方案，后来在ShareHive被“三项独立卡片、去箭头”替代。二者是项目迭代，不可推成一律合并或一律三卡。

紫色、近黑、220px卡高、top:-120px、人物底边0px、单文件6MB限制属于当时项目约束。ClickUp局部材质获得欣赏，也不意味着用户固定喜欢所有暗色页面。

## 冲突与更新

当前明确需求优先，其次是当前已批准约定；历史个人反馈只在条件匹配时采用。参考观察和助手推断必须保持候选地位。安全、隐私与当次授权边界不因风格偏好而改变。

用户要求新增网站时可将其标成“用户提供且希望研究/喜欢整体”；具体布局、字体、动效仍需逐项校准。把未来反馈区分为长期判断、风格条件或项目决定，确认可复用范围后再更新本文件，并保留替代关系。
