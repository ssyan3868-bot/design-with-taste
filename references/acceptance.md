# 验收：把判断与事实分开

先确认当次授权、任务模式与已选风格，再验收结果。没有选择的新设计以“给出适配候选并明确等待”为成功，不以生成页面数量为成功。

## 过程门槛

- 新需求按[预期卡规范](style-language.md#推荐卡格式)给出通常 2–3 个适配候选。用户能通过具名主链接与浏览区域知道看哪里，通过本项目描述知道预计得到什么、与参考有哪些差异、素材能否支持；仅列网站名称或抽象形容词不算完成。
- 候选前说明已知交付范围；默认不出图或制作样张，不为速选遍历所有外站。历史依据明确日期/范围；链接可达与画面核验分别记录，已知改版或访问失败不继续承诺旧画面。
- 尚未选择时停止，不提前写约定或代码；含糊“继续/都看看”不构成选择，否定/调整后重筛选，不自动替用户选第二项。
- 已选方向且获准制作时，首屏与代表模块是内部检查点，不额外强制样张审批；普通延展不重复询问，重大风格变化说明差异并请求确认。
- 新增参考按多标签和来源归类；观察、推断、用户确认分离。失败访问不写成成功研究。
- 产品功能展示按[候选决策表](product-feature-options.md)核对：推荐解释数量、权重、素材与整页关系，保留使用者选择权；不把四类候选当作四套必做页面，不将截图里的箭头/暂停符号或用户描述写成已测试交互。
- 营销 Hero 按[主视觉候选](hero-options.md)核对：说明文案、产品展示、人物场景与装饰的职责；保留用户归类和选择权。上下结构不等于统一纯色背景，有人物不自动归方案3，缺图链接不算已观察案例。

## 视觉审阅

| 维度 | 查看什么 | 不可用什么替代 |
|---|---|---|
| 主次 | 第一眼是否落在应关注的标题、主体或工作区；次要信息是否抢位 | 元素无溢出不等于主次清楚 |
| 主体与内容 | 人物头部/动作、产品关键操作、正式文案是否完整；叠层是否解释而非遮挡 | 单看坐标或只看局部截图 |
| 风格连续 | 字级、图像体系、材质深度、密度和章节节奏是否遵循约定 | 全部使用同一种颜色 |
| 章节节奏 | 不同内容角色是否得到合适分组，过渡是否有意图 | 每节复用同一卡片栅格 |
| 阅读与材质 | 玻璃覆盖装饰但不压低正文清晰度；深底浅字、强调有节制 | CSS写了blur就算实现质感 |
| 适配 | 长文、窄屏、空数据下是否仍清楚；图像主体是否保持 | 桌面截图缩小显示 |

至少实际打开首屏、代表模块和关键长内容状态；大幅改版看整页衔接。参考截图与新页面按相近视口对照，但不把像素相同作为审美目标。

## 工程核对

按页面实际功能选择检查：文案完整、链接目标、无意横向滚动、图片失败回退、键盘Tab及焦点、按钮/表单语义、对比度、移动重排、减弱动态。正文对比度以适用的WCAG阈值检验，而非仅凭颜色名称。复杂表格如需横滚，应限制在有标识的局部容器，不能让全页意外横滚。

应用界面额外检查加载、空白、失败、权限、保存反馈及真实任务流。无后端的小样只证明展示/已实现交互，不能声称业务可用；示例指标必须标注虚构。

只观察了桌面就写桌面，静态截图不能证明动画舒适，DOM文字不能证明图片质量。工具不可用时列出未验证项，不虚报通过。

## 工具受限时的降级与基线

- 截图工具失败（例如视口不可用、浏览器连接中断）时，降级为结构快照或 DOM 检查验证内容与层级；视觉状态在交付记录中明确记为"未验证"，不得写成视觉已通过。
- 重大改版开始前，工具可用时先抓基线截图或结构快照，便于改版前后对照；未抓基线要在交付记录中注明。
- 降级路径不替代视觉审阅：仅当截图确实不可用时启用，且只覆盖结构与内容层，不宣称视觉、动效、材质已验证。

## 可重复迁移测试

1. 输入虚构简报但不给风格选择，检查候选与等待行为，没有页面文件变更。
2. 给明确标注的模拟否定/调整，检查重筛选与再次等待。
3. 给明确标注的假定选择（非真实偏好），才制作测试约定和少量小样。
4. 同一简报选择两种合理方向，比较构图与图像语法，而不是只看深浅换色。
5. 同一方向新增章节、增加文案长度，检查不变量与布局适应性。
6. 检查营销/作品/阅读/应用的角色路由，以及判断规则中各项明确反例的条件边界。
7. 以已有来源模拟新增库输入，验证去重、多标签、证据状态；不污染真实偏好库。
8. 用不同数量、权重、文案和素材条件的功能简报，检查是否筛选而非固定四选一；保留选择门槛，并能区分 Airtable 静态图文正例与强动效反例、语义用色与模板装饰。
9. 用产品证据充足、人物场景优先、文案主导三种 Hero 简报，检查图像职责、素材与候选理由；不因有人像或上下结构重分类，不把纯色/小插画固化到全部方案 2，保留选择门槛；对 Braze 缺图和钉钉占位链接如实说明，不补造观察。

### 参考网站速选的增补场景

在上述迁移测试中复用重叠输入，不另做一套重复测试。补足以下断言：

| 输入/状态 | 核对结果 |
|---|---|
| 新营销首页；品牌/内容已知、未选方向 | 适配的 2–3 项含具名主链接、浏览区域、本项目预期/差异及素材条件；无生图、页面或约定写入 |
| “先给链接，我想自己浏览” | 简短速选，不强制问卷、截图拼板或样张 |
| “继续/都看看”而非明确选择 | 不自动选择或开始制作 |
| 否定营销候选，改要内容杂志 | 重新按阅读角色筛选，可用类外方向，不强迫营销四选一 |
| 缺产品图；参考不可访问或已改版 | 标明素材/证据缺口，不造观察、不静默换载体；模拟工具失败须标为模拟 |
| 明确选择并授权制作测试页 | 约定承接预期，不强制额外样张审批；只在隔离目录制作，按选定承诺核对 |
| 已选方向增加长文/手机布局 | 保持身份，允许必要重排；不重复选方向，不删正式内容 |
| 产品后台任务 | 使用应用角色路由，不套营销 Hero 四类 |

选择后的验收使用[预期映射](style-contract.md#承接选定的产出预期)，逐项对照承诺与实际画面。“产品先行”要看到可辨识的产品场景，不是存在图片即通过；“分权重”要看内容与注意力，不是卡片较大即通过。完整视觉审阅仍按上文执行。

以上为测试规格，不代表已经执行。用独立执行者、隔离目录和明确标记的模拟简报实际运行，给 Skill 与输入、不喂期望答案。根据用例允许测试目录内的制作，不通过禁用全部写工具制造“选择前不写文件”的通过结果。记录真实输入、输出、工具轨迹、文件变化和证据；不改生产页面、个人记忆或偏好库。人工通读提示词不能替代真实运行；手动加载 Skill 的独立 agent 测试不等于宿主自动触发。

## 交付记录

分别列“已完成”“实际验证”“未验证/限制”。给入口和产物链接，不把未经执行的测试写成通过。交付和工程验证不等于用户认可成品，不自动写成成功案例。个人全局安装后核对文件一致性；只有宿主重新加载且真正调用成功，才写“触发已验证”。

包结构可由 [check_bundle.py](../scripts/check_bundle.py) 检查，含索引与案例目录一致性；它不验证互联网链接、浏览器行为、调用注册或视觉质量。
