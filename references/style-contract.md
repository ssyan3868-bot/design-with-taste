# 项目风格约定

仅在用户明确选择方向后填写。推荐候选不是约定；示例不是默认值；参考网站不是整站复制授权。约定保存在当前项目的已有设计文档或用户批准的位置，不自动写回全局案例库。

## 必需字段

| 字段 | 记录内容 |
|---|---|
| 身份 | 项目、页面角色、约定版本、记录日期、方向名称和一句话定义 |
| 选择依据 | 用户真实选择的消息/可追溯摘要及附带限制，不虚构批准 |
| 内容目的 | 面向谁、主要行动、内容量、优先信息、不可删改文案 |
| 参考职责 | 每个真实URL、观察范围/日期、借鉴区块、排除项；组合时的职责分工 |
| 构图 | 主次、对齐、图文比例、图片主体安全区、章节之间如何变化 |
| 密度与字级 | 标题/正文/注释/状态的层级；中文长文和窄屏如何适应 |
| 色彩职责 | 背景、文字、边界、行动、状态分别承担什么 |
| 图像语法 | 照片/产品UI/插图的地位、裁切规则、是否允许透视/叠层 |
| 材质边界 | 渐变/玻璃/纹理出现在哪、覆盖谁、强度上限；文字独立清晰 |
| 章节节奏 | 每节的任务及可采用的构图组合，不是重复卡片清单 |
| 交互与适配 | 状态反馈、导航、键盘、小屏重排、减弱动态、素材/效果降级 |
| 项目参数 | 本项目的颜色、间距、字级、圆角、断点等；与简报和实际内容一起推导 |
| 不变量 | 延展必须保持的3–6条可观察特征 |
| 可变量 | 可以换哪些布局、图片比例或内容分组，以及条件 |
| 排除项 | 已确认不适用的处理与原因，标清是项目限制还是长期规则 |
| 再确认门槛 | 哪些变化会构成改换风格；谁确认、如何记录 |
| 验收证据 | 批准页面/截图、对照部位、已验证和未验证状态 |

## 承接选定的产出预期

把[推荐卡](style-language.md#推荐卡格式)的选择与限制写入现有字段，不另起一套约定：方向归“身份/选择依据”，主参考与浏览范围归“参考职责”，本项目画面归“构图/章节节奏/交互与适配”，素材条件归“图像语法”，相似与差异归“不变量/可变量/排除项”。分清用户已确认承诺、助手暂定假设和待补素材，不把推荐中的条件句改成无条件保证。

在“验收证据”下列出少量可观察的 **预期 → 实现部位 → 核对证据/状态**。例如选定“产品先行”后，对照目标视口中主产品场景是否可辨识，不能仅凭存在一张图判通过；选定“分权重功能展示”后，对照内容和实际注意力，而不是只测卡片尺寸。截图工具不可用则视觉状态为未验证，不能用代码或 DOM 冒充已看画面。

素材缺失或不适配时保留缺口；提出替代及影响，触及图像/风格身份变化时再确认，不静默改成另一载体。长文或窄屏的必要重排可写入可变量，普通适配无需重复选方向。最终交付不等于用户认可成品，也不自动形成全局成功案例。

## 演示：不是用户选择

以下为虚构产品站的字段演示，不能当真实项目指令。

- 定义：产品证据主导的明亮叙事，浅底承载短命题与大幅业务界面，颜色只强化关键动作。
- 参考职责：monday用于平台价值到产品证据的层级研究；Instantly用于按业务步骤展开场景。引用这些站不代表当前页面已被重新核验。
- 不变量：主体界面优先于装饰；标题与证据在一屏内形成明确关系；一套稳定字级；材质不覆盖正文；每节只有一个主要论点。
- 可变量：从左右结构换成单宽图、从列表换成流程；长文时增加高度并调整分组，而非删字。
- 排除项：首屏大量同权浮卡、装饰粒子追随指针、无素材支持的假客户评价。
- 再确认：把页面整体改为近黑沉浸式，或把产品证据改为人物照片主导，属于身份变化。

该演示不预置真实项目的色值、字号或卡片数量，不产生“已批准”状态。

## 延展协议

先写一段变更摘要：保留了哪些不变量、为什么调整布局、是否触及排除项。普通延展不重复选择风格；内容变化明显但身份不变时，可通过新的分组和断点适配。

局部精修锁定区域、保留文案及相邻章节，先修主次和遮挡，再增加材质。不因单个新模块“更酷”就引入另一套字级、图形风格或动态系统。

## 冲突处理

优先遵循当前明确需求和已批准项目约定。历史判断仅在相同条件下使用；案例特征与助手推断不凌驾用户选择。若当前需求与约定确实冲突，指出具体冲突和受影响区块，取得明确方向后更新版本。

真实选择、模拟测试和助手推断分别标记。更新约定不代表允许重写全局个人规则，研究参考也不代表允许复用第三方品牌资产。
