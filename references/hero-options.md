# 营销 Hero：四类候选与选择规则

## 范围与确认状态

2026-09-21，用户补充“营销 Hero 主视觉”，给出四类方案、十个来源链接及九张截图。以下沿用用户编号，作为可按简报筛选的候选库，不是当前项目已选方向、四套必做页面或封闭风格全集；不自动覆盖产品功能卡、行业卡或真实应用界面的规则。

九张截图已实际打开并原样归档。本轮不访问在线页面；收图/整理日不等于拍摄日，图片像素不等于 CSS 视口。Braze 只有链接及用户归类，暂不作视觉事实。下文适配条件、取舍与验收建议是设计推导，不冒称用户逐项确认或已做效果实验。

## 先判断图像职责，再推荐

1. 明确首屏要先回答的问题：产品做什么、怎样工作、为谁服务，还是品牌承诺是什么。确认主行动、标题长度、核心证据、素材与下一章节的关系。
2. 按图像的叙事职责分类，不只按有无人像、左右/上下或背景颜色分类。同样的照片可解释使用情境，也可退居文案旁的氛围层；同一案例允许多标签，但保留用户原始归类。
3. 筛选通常 2–3 个适合的方向，给具体名称、画面、适配理由、真实参考及观察范围、素材要求和取舍，保留使用者选择权。没有足够适合候选时不凑数。
4. 选择前不生成页面、项目风格约定或图像试样；选择后才细化布局与制作方式。普通延展不重复询问，图像体系变化依 J13 重新确认。以下认可不授权更换现有项目的 Hero。

## 四类候选

将四类作为稳定的营销首屏浏览入口，不当作四套整站模板或封闭全集。按需求推荐适配项，用户要完整目录时才全列；后台、阅读和作品页面按各自角色筛选，不套此表。使用[推荐卡格式](style-language.md#推荐卡格式)说明本项目预期与差异，功能区独立选择，不按编号搭配。

下表的主参考均来自既有证据，收录于 2026-09-21，截图拍摄时间未知，非本轮在线核验。建议浏览区域描述的是留存画面；当前页面可能变化，证据局限见下方映射。网站名帮助浏览，不固定其颜色、字体、材质或整站结构。

## 类内差异：不把参考压成一个模板

### 方案1：简洁不等于没有产品含义

飞书截图为 CodeM 浅色横幅：左侧产品标识、主副标题、短说明、CTA，右侧通信窗口与智能体任务状态，局部悬浮标识和柔和投影。它和此前飞书深色大会 Hero、邻近色功能卡是不同范围的证据。可借鉴右图聚焦、左右呼应，不继承大会弹窗、自动轮播、固定栏宽或默认蓝紫色。

### 方案2：共同点是主张到产品证据的上下顺序

- 钉钉：白底、大字、蓝色手绘划线、对话气泡和小插画形成局部强调；下方标签与 AI 听记界面。小插画有语义和位置职责，不是给每个词塞图标。
- Sider：白色标题区与宽浏览器展示；渐变颗粒舞台托住 UI。重点是浏览器主体与侧栏任务的关系，不必复制品牌渐变或信任数字。
- Slack Code：深紫色、透视/弯曲网格背景；聊天与代码变更层叠展示协作含义。共同结构得到认可，不等于满屏网格被确认为通用装饰；本例也不推翻 J11 对无业务科技素材的限制。
- Monica：居中标题与说明，宽主界面和窄侧栏形态叠放，浅粉紫背景承托。不能仅凭宽窄认定为桌面与手机；较长说明、模型清单、悬浮奖章都不是必抄部分。

### 方案3与4：以注意力和叙事分工区分

Gong 的通话人物与跟进提示共同解释销售情境；Copper 以多行业人物照片表达关系与服务对象。Fueler 则让人物头像分布于中央文案周边；Quicken 把照片、人物出框与财务卡整合在主张下方，文案与行动仍优先。不要把 Copper 改归方案2，只因它上下布局；也不要把 Quicken 或 Fueler 强行改归方案3，只因它们出现人物。

采用方案3时，“真实人物增加信任感”是用户的设计意图，不是已验证的因果效果。真实照片不自动等于真实客户，生成或库存人物不得冒充客户/证言。采用方案4时，可用头像、场景、形状或少量指标辅助，但不能以“装饰”为由使用虚假人数、收益数据或无关素材。

## 共同制作与验收重点

- 先写清一项主要价值主张及主行动，再确定首屏视觉重心。精致标题来自断行、字重、行宽、语义强调与图文对齐，不是照搬截图字号；中文长标题不强行套英文单行结构。
- 允许小插画、照片、图形与 UI 按各自职责出现。钉钉的点睛小插画和 Fueler 的文案周边装饰，不等于重新认可 R04 的过时扁平商务插画，也不等于全站可堆表情符号。无需复刻参考中的每个装饰。
- 区分表现载体与实现方法：真实截图、局部 UI、抽象/重绘示意、照片与图形组合可分别采用合适技术，不统一降为 CSS mockup。示意需标明，不冒充上线功能或真实操作结果。
- “简洁、有质感”要落实到主次、裁切、边界、尺度和光影；不能把玻璃、渐变或更多叠层当作必选项。若背景纹理抢走标题和产品焦点，应减弱或移除。
- 照片要与文案、色调和容器构成整体；融合不强制紫色渐变，也不授权随意复杂抠图。需要出框时保留头部和关键动作，卡片避让主体；素材与生产方式先按已选方向确认。
- 首屏高度按真实目标视口验证，不把截图裁切处当作设备折叠线。窄屏建议图文顺序相邻、减少周边装饰/叠层，但保留主要产品含义；不能把桌面整体缩小。以上为新实现要求，非原站实测。
- 飞书底部进度条、钉钉标签、视频入口、叠层界面和侧边浮标只证明控件/图形可见，不证明自动播放、切换、滚动、悬停或业务操作。新实现若需要这些交互，另验键盘、触屏和减弱动态。
- 引用用户数、奖项、模型名/版本、营收与财务图表前独立核实。截图只证明该文字被展示，不证明声明真实、最新或适合新项目；示意数值应明确标注。
