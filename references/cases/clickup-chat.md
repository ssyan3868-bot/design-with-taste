- 范围仅为截图中的聊天功能展示区；中文标题说明与英文示意界面混合，不代表整站语言。

## 截图事实
- 近黑底上以圆角、细边框分隔卡片，局部卡角可见彩光。
- 左侧“连接任务”为高卡，右侧上下为“帖子”“后续跟进”两卡；下排另有三张卡。
- 各卡标题与描述置顶，简化聊天 UI 位于下方，图文在同一容器中。
- 次要消息以灰线、淡化内容呈现；任务关联菜单、关键按钮和提示更突出。

## 解释与推断
- 图文共同说明一个功能，可能降低读者在文字与图示之间寻找对应关系的成本。
- 高卡容纳纵向菜单，短卡承载局部操作；跨行布局可服务内容差异，而非只为装饰。
- 淡化非关键界面有助于聚焦，但这是视觉解释，不是可用性或转化效果验证。

## 用户确认范围
- 用户方案1：标题＋描述＋配图，风格统一、文案含义明确、美观且不拥挤；按功能数量考虑布局。
- 确认为“产品功能展示的可选方案”，不是整站喜欢、项目选定或 UI 操作已验证。

## 多维标签
- 用途／叙事：产品营销功能说明；功能主张→局部界面证据。
- 布局／密度：跨行高卡＋双卡＋下排三卡；说明区疏朗、界面局部紧凑。
- 字级／图像：标题优先、描述次级；简化聊天 UI；字体家族与精确字级未知。
- 材质／色彩：近黑底、细边界、圆角、局部彩光；暗色不是通用偏好。
- 状态／偏好：单张静态截图；方案1局部正例，动态行为未验。

## 条件化迁移
- 功能权重与篇幅接近 → 等分图文卡 → 便于平行浏览；数量不固定为六卡。
- 某功能篇幅较长或 UI 偏纵向 → 适度跨行 → 给内容足够空间；同时权衡数量、权重、篇幅与 UI 纵横比例。
- 功能需解释具体动作 → 保留相关菜单与提示、弱化无关消息 → 明确文案含义；真实操作页不能据此隐藏必要信息。
- 内容很少或需长流程讲解时，不强凑复杂网格；窄屏按阅读顺序保持每组图文相邻，此为建议而非已观察行为。

## 不照搬项
- 不复制 emoji 装饰、低对比正文或固定六卡结构；彩光不能代替内容层级。
- 不将营销示意 UI 当作完整产品流程，不把深色与品牌配色写成项目默认值。

## 证据限制与附件
- 未验证滚动、悬停、按钮、真实聊天与任务操作、窄屏重排或无障碍表现。
- 不补猜字体、实现技术、动态参数；截图只作研究证据，不附带素材复用授权。
