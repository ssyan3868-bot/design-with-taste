# 产品功能展示：四类候选与选择规则

## 范围与确认状态

2026-09-21，用户提供六张截图及页面链接，明确列出以下四类可选方案，要求“根据产出整体效果匹配适合的，也应该给使用者选择方案的权利”。这是营销页面内的功能展示分类，不是真实产品应用规范，也不是四套整站模板；不据此推断 Hero、行业卡或其他尚未确认场景。

四类均为用户认可的候选，不是当前项目已选方案，没有固定优先级。下文“适用条件、取舍、重排建议”是基于参考的设计推导，不冒称用户逐项确认或网站实测结论。后续可新增类型，不把四类当作全集。

## 先匹配，再交给使用者选择

1. 提取功能数量、主次权重、每项文案长度、需表达的业务动作、可用图片/UI 素材、页面前后章节与已有风格；区分“并列了解”与“依次讲解”。不只凭数量或品牌颜色选方案。
2. 从下表筛出通常 2–3 个真正适合的方向。每个方向给命名、对应内容的构图、适配理由、真实参考及借鉴区域、素材要求、主要取舍和窄屏思路；说明推荐项，但保留更换或调整的权利。候选不足时说明原因，不为凑数推荐不合适的方案。
3. 未选定时明确等待，不以“整体效果更好”为由替用户决定并开始页面、图片或项目约定制作。用户修改/否定后重新筛选；已选方案的常规内容延展不重复询问。变更载体/材质语言遵循 J13。
4. 选定后先形成一项代表功能的“标题主张 → 可见界面动作或结果 → 配图焦点”，再统一延展。保持图像语法一致，不要求每张卡片布局完全一样。

## 配图与布局的共同原则

- **配图是功能说明，不是填空装饰。** 可以放大关键控件、对话、任务对象或业务结果，弱化背景信息；必须能解释为何这幅图属于这段文案。无意义灰条加窗口边框不自动构成合格产品配图。
- **把表达方案与制作技术分开。** 整图截图、真实 UI 局部裁切、重绘/抽象界面、照片组合都是载体；CSS/SVG、设计资产或其他制作方法由准确性与素材决定，不把四类机械映射成“都用 CSS mockup”。涉及具体操作/真实性的主张优先用真实证据；示意界面标明示意，不冒充实际产品截图或已上线功能。
- **统一语法，不统一内容。** 同组保持字级、圆角、UI 精简程度、光影方向、边界和色彩关系；根据不同功能换内容焦点。截图里的品牌标识、人物头像、表情和商标不是应复制的装饰素材。
- **数量影响布局，但不决定布局。** 类似权重可等分；较重要或纵向 UI 较长的功能可跨行；功能增加时先分组或换行，不不断挤小字与图片。跨行主卡的视觉主次应有内容理由。
- **颜色与材质有职责。** 可用邻近色背景区分能力、不同底色组织大卡片节奏、局部渐变/轻阴影建立前后层次；不要把用户对模板化彩色顶条的否定扩大成禁止所有彩色功能卡。轻毛玻璃是视觉目标，截图不证明实际用了 backdrop-filter。
- **照片服务情境，界面服务功能。** 选照片时预留适合 UI 的空域，协调尺度、光线与色调，不遮人物脸部或主要动作；照片来源和复用许可另验。摄影质感不证明素材一定来自实拍。

## 各方案的实施与验收重点

- 方案 1：对照最短/最长两项文案检查图文映射、留白和视觉权重；每张图保留关键含义，次要 UI 可以弱化，但正式正文不能随背景消失。
- 方案 2：采用滚动关联时，逐段测试文字与图像一一对应、展示区不遮挡下一节、反向滚动不失配；窄屏可改为每段文字后接对应图像，减弱动态时保留所有内容。以上是新实现要求，非 Calendly 已验证行为。
- 方案 3：检查整张大卡与相邻章节的色彩节奏、照片主体和 UI 可辨识性；变色只改变分组/氛围，不破坏对比度。静态叠放发票不代表需要动效。
- 方案 4：检查短标题和抽象 UI 能否区分每项业务；小图表仅作示意时不能输出未经证实的业绩数据。若横向浏览，按钮、键盘、触屏和非横滚替代布局需另验，不能将整页撑出横向滚动。
