初次整理：2026-09-20；最近补充：2026-09-21。逐页浏览或收图时间见案例，不套用同一个访问日期。

本库复用审美判断、信息关系和条件化手法，不统一所有页面的风格。案例按任务与证据检索，来源与边界见各卡。

## 用户确认与证据规则

- 入库不等于“用户喜欢”，未批评也不等于偏好；具体认可对象按案例记录，不扩大到整站。
- 网站参考的历史排除为 WPS 首页 Banner“展示方案太散”、Airtable 项目管理页“动效过强”；另有 Neocrm 模板装饰和扁平商务插画反例，详见判断规则 R01–R04。排除对象不可扩成全站、所有配色或所有 grid。
- ClickUp 图文整体性与卡片材质曾获项目内欣赏；2026-09-21 用户进一步确认指定首页/Chat 功能区域可作方案 1，不是通用暗色或紫色 AI 偏好。
- shadcn、Excalidraw、Pentagram、Stripe 四组补充来源用于扩充覆盖，不构成整站审美背书。
- 2026-09-20 新增九组为用户指定研究。2026-09-21 对 ClickUp 首页、飞书和 Quicken 等指定区域的局部确认见更新卡，其余区域不自动升级为用户偏好。
- 2026-09-21 六张用户截图对应四类[产品功能展示候选](product-feature-options.md)：统一语义配图卡组、左文右图滚动讲解、照片与 UI 大卡、邻近色轻质感卡。四类为可选，不是当前项目已选。
- 同日另有九张截图、十个来源链接对应四类[营销 Hero 候选](hero-options.md)：左右精简产品图、上下产品展示、人物场景与能力图形、文案主导的融合式氛围。按图像职责分类，保留类内差异和使用者选择权，不与功能方案编号机械配对。
- Hero 中 Braze 仅有链接与用户归类，未观察画面，不计入已观察案例；钉钉深链含占位符，未打开或替换参数，旧下载页记录不证明新 Hero 来源地址。
- Airtable 营销页静态图文正例与项目管理页强动效反例分别记录，不互相覆盖。Calendly 滚动固定区域、Wise 多卡底色节奏来自用户描述，未做浏览器行为验证。
- 区分事实观察、解释推断、用户确认和未验证项；截图不证明字体实现、素材授权或完整操作。功能六图与 Hero 九图均为正向候选材料，不作为 R04 插画负例。

## 条件化检索方式
1. 先写清页面任务、受众、内容资产、信息密度、语言和必要状态，再选入口；应用功能的营销页不等于真实产品应用证据。
2. 交叉筛选“叙事关系 + 布局角色 + 图像用途 + 字体证据 + 材质目的 + 状态覆盖 + 用户确认”，不要只搜蓝色、暗色或玻璃。
3. 例如“多角色平台，需要具体业务证据”可查 monday；“同品牌单产品需要独立构图”可对照 WPS 两页，但排除首页 Banner 的已否定方案。
4. “工作台概览到明细”先查 shadcn 的位置层级并标记业务缺口；“画布初次进入”查 Excalidraw，不能宣称保存流程已验证。
5. “成果需要图像解释”查 Pentagram；“文章需要持续阅读”查 Stripe。缺少图片或实际语言不同，都应重新判断适用条件。
6. 从案例提取“在什么条件下，以什么手法解决什么问题”，再列不适用条件与反例；若证据不足，明确缺口，不以最像某站代替判断。

## 新增研究卡
先创建案例，再添加相对 Markdown 链接；不要预留指向不存在文件的链接。每例建议 40–65 行，沿用以下字段但不强凑未观察信息：

```text
案例标识与标题：独立命名，保留具体页面而非只写品牌
来源：请求 URL / 实际 URL / 来源性质
时间：整理日期 / 初次浏览及精度，无法复核则明示
语言与观察范围：实际语言 / 桌面视口变化 / 页面位置 / 操作边界
事实：只写记录中出现的布局、字体、图像、材质与状态
推断：解释可能作用，注明不是验证结论
用户确认：研究纳入 / 项目内欣赏 / 明确排除 / 未确认，写清对象与语境
多维标签：范围、任务、叙事、布局、字体、图像、材质、状态、偏好证据
条件化手法：适用条件 → 手法 → 预期作用；附不适用条件
不照搬项与反例：明确局部对象，不升级为全局禁令
证据局限：未观察状态、未验证行为、授权与语言缺口
附件：只链接实际已创建且能对应来源、位置和视口的证据
```

追加时允许新增标签与跨类归属，不以既有案例为审美上限；偏好变化保留原语境，新增证据不要覆盖成“始终喜欢/讨厌”。
